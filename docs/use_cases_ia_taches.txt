USE CASES IA - VS CODE + DUCKDB + CLAUDE CODE + CLAUDE API
============================================================

Objectif : mettre en place un socle local d'intelligence artificielle
pour l'analyse de donnees, l'assistance au developpement et l'automatisation.

Principes :
- Les donnees restent en local dans DuckDB.
- Claude Code assiste l'ecriture de code, SQL et transformations.
- L'API Claude est reservee aux taches de raisonnement, synthese,
  classification, extraction et generation de rapports.
- Toute ecriture en base ou modification de fichier doit etre validee.

------------------------------------------------------------
1. PREPARATION DE L'ENVIRONNEMENT
------------------------------------------------------------
[ ] Creer un dossier projet dedie, par exemple : ia-copilot/
[ ] Creer l'arborescence :
    ia-copilot/
      data/raw/
      data/staging/
      data/marts/
      db/
      sql/
      reports/
      scripts/
      tests/
      docs/
[ ] Installer et verifier DuckDB en local.
[ ] Installer l'extension Claude Code dans VS Code.
[ ] Configurer la cle API Claude dans une variable d'environnement,
    jamais dans un fichier versionne.
[ ] Creer un depot Git avec .gitignore protegeant :
    - les donnees brutes
    - les bases DuckDB
    - les fichiers contenant des informations personnelles
    - les secrets et cles API
[ ] Creer un fichier CLAUDE.md decrivant :
    - le contexte du projet
    - les conventions de nommage
    - les regles SQL
    - les donnees sensibles interdites
    - les commandes autorisees et interdites
[ ] Creer un fichier README.md expliquant comment lancer le pipeline.

3. USE CASE 1 : ANALYSTE DE DONNEES LOCAL
------------------------------------------------------------
Objectif :
Permettre a Claude de repondre a des questions metier sur les donnees
locales via DuckDB, puis produire une analyse claire.

[ ] Creer une vue metier propre a partir des tables staging.
[ ] Definir 5 a 10 indicateurs utiles, par exemple :
    - chiffre d'affaires
    - marge
    - nombre de clients actifs
    - taux de conversion
    - taux de retention
    - churn
    - nombre d'incidents
    - delai moyen de resolution
[ ] Ecrire les requetes SQL correspondantes dans sql/.
[ ] Tester chaque requete sur un echantillon de donnees.
[ ] Creer un prompt type :
    "Analyse ce fichier avec DuckDB. Profile les colonnes, identifie
     les anomalies, cree une table propre, puis reponds a la question
     suivante : [QUESTION]. Sauvegarde le SQL et le rapport."
[ ] Demander a Claude de produire un rapport Markdown dans reports/.
[ ] Ajouter les graphiques necessaires :
    - evolution dans le temps
    - repartition par categorie
    - comparaison de segments
    - anomalies
[ ] Mettre en place une commande reproductible pour relancer l'analyse.
[ ] Verifier manuellement les premiers resultats avant diffusion.

Livrable attendu :
- Base DuckDB propre
- Requetes SQL versionnees
- Rapport d'analyse automatique
- Reponses aux questions metier avec sources et methodologie

- devis

[ ] Exemple pour une facture :

      "montant_ht": 0,
      "tva": 0,
      "montant_ttc": 0,

      "categorie": "",

[ ] Utiliser l'API Claude pour extraire les champs.
[ ] Valider les champs obligatoires et les formats.
[ ] Enregistrer les resultats dans une table DuckDB.
[ ] Conserver le document source et son identifiant.
[ ] Signaler les extractions a faible confiance.
[ ] Mettre en place une revue humaine pour les documents sensibles.
[ ] Creer des requetes d'analyse :
    - total par fournisseur
    - total par mois
    - factures en retard
    - categories de depenses

Livrable attendu :
- Table DuckDB structuree
- Extraction JSON controlee

- Recherche et agregations possibles
